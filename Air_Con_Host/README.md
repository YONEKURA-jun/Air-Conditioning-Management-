技術実績・開発経歴書

概要・コアスキル
OS（Windows API）が提供するシリアル通信インターフェースをC言語から直接制御する実装力を保有。実際の検証環境（USBシリアル）から将来的な産業用RS-485マルチドロップ通信まで見据え、端末IDと通信ポートの紐づけ管理、タイムアウト処理、ログ永続化を備えた保守性の高いシステムを設計・開発できます。

開発言語: C言語

OS / API: Windows API (Win32) (CreateFile, SetCommState, SetCommTimeouts, WriteFile, ReadFile)

通信・プロトコル理解: シリアル通信（UART/USBシリアル）, RS-485マルチドロップ構成の想定設計, 固有ID識別・状態フラグ同期プロトコル

制御・処理アルゴリズム: 定期巡回（1時間周期ポーリング）, 過去6時間分データバッファリング / コンソール表示

データ管理: 構造体によるメモリ管理, テキストファイル（.txt）による接続設定（ID・COM紐づけ）およびログデータの永続化

検証・対象環境: Windows PC（ホスト）, USBシリアル接続, Arduino（スレーブ端末15台想定）

主要開発実績プロジェクト
ビル空調管理システム向け ローカル監視・状態管理プログラム（プロトタイプ）
Windows PC（ホスト）からシリアル通信経由で15台のArduinoスレーブ端末を一括制御し、端末の状態管理・環境データの取得・永続化・履歴表示を行うシステム。

1. システム仕様・設計要件
設定ファイルによる接続管理（ID・COMポート紐づけ）:

外部テキストファイル（.txt）にて ID0014,COM12 のように端末IDと接続ポート番号（アドレス）をペアで定義。

起動時に設定ファイルをパースし、IDごとに対応するCOMポートを開いて動的に割り当てる構造とし、ハード構成変更時の保守性を確保。

通信構成（実環境と想定設計）:

実環境: USBシリアル通信による実証・データ送受信検証

設計想定: 将来的なRS-485 2線式マルチドロップバス化を見据え、データ衝突を回避するID割り当ておよびポーリング設計を採用

通信周期・状態管理:

1時間に1回の定期巡回（ホスト主導の指名点呼方式）

各Arduino端末の固有ID識別と、端末内部の「稼働状態フラグ（通常／停止／警告など）」の同期

ログ保持・画面表示: 取得データをファイルへ自動保存。起動時に過去6時間分の履歴データを読み込みコンソール画面へ表示

データ保存形式: 外部フォルダ内のテキストファイル（.txt）へ以下のフォーマットで追記保存
[ID] [温度・湿度] [稼働状況フラグ] [日時 (YYYY-MM-DD HH:MM:SS)]

2. 担当役割および実装工夫点
Windows APIを用いたシリアル通信層のローレベル実装

高レベルライブラリを使わず、CreateFile や SetCommState (DCB構造体) でポート・通信パラメータを直接設定。

COMMTIMEOUTS 構造体を適切に設定し、特定端末の応答なし（断線・フリーズ等）が発生しても全体の処理ループが停止しない例外処理を構築。

設定ファイル（ID・COM対照表）のパースと動的制御

テキストファイルから ID と COM 文字列を読み込み、\\.\COM12 形式のデバイスパスへ整形して CreateFile に引き渡す柔軟な接続処理を実装。

電文フォーマット解析とデータ構造化

受信バッファ（バイト配列）から「ID」「温湿度（センサ値）」「稼働状態フラグ」を抽出し、C言語の構造体へ正しくマッピングするパース処理を実装。

ファイルI/Oによるデータ永続化と履歴復元

1時間ごとの収集データをタイムスタンプ付きでテキストファイルへ保存。起動時には直近6時間分のテキストログを走査し、画面描画する処理を構築。

技術的強み・アピールポイント
1. 現場運用・保守性を意識した外部設定設計
プログラム内へのハードコードを徹底的に排除し、ID,COMポート の対応関係を外部テキストファイルで管理する設計を採用。USBポートの挿し直しや機器交換が発生した場合でも、ソースコードの再コンパイルなしで設定ファイルの更新のみで即座に復旧できる実務的な設計力を備えています。

2. OS（API）とハードウェア境界の確かな理解
アプリケーションが直接ハードウェアを操作するのではなく、OS（Windowsカーネル）のAPIへ構造体経由で設定・命令を渡すという基本原則を正しく理解し、安全なコードを記述できます。

3. 実務を想定した堅牢な処理設計
単なるデータ受信にとどまらず、端末の「稼働状態フラグ」の監視、通信断時のタイムアウト処理、テキストファイルへの安全なログ保存、過去データの再読み込みなど、運用面まで考慮したロジックを自力で組み上げられます。
